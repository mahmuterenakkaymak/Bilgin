# Visual review — M25 (connections, db status dot, threads, board, ready questions, rules, users, map, dark mode)

Caveat first: every chart in this run renders the **pre-T377** option — the pie carries a `legend: {type: "scroll"}` paging 2 of 5 names behind "1/5 ◀" (conversation-three-turns-turn-3-chart-only-390.png) and the bar names sit in 160 px boxes, which is what HEAD no longer emits. The run drove a server older than the working tree, so the chart items below are only what T377 does not already cover.

## Real problems
1. **Conversation thread · both widths** — a collapsed earlier turn prints the raw SQL alias while the card directly above or below it prints the prettified label: turn 1 reads `URUN_ID | URUN_ADI | SATIS_MIKTARI` and turn 2 reads `Ürün id | Ürün adı | Satış miktarı` (conversation-three-turns-turn-2-follow-up-1366.png, conversation-three-turns-earlier-turn-expanded-390.png, card-answer-followup-pinned-1366.png), and the same split shows `CountryName / SEHIR_SAYISI` against `CountryName / Sehir sayisi` (conversation-chart-refine-only-ankara-1366.png). `TurnCard.jsx:89` renders `{name}` while `ResultTable.jsx:46` renders `columnLabel(name)` — T379's own comment excludes the collapsed table, and that exclusion is the defect: one thread, two naming styles, the older turns looking like a different, uglier product.
2. **Ready questions · admin** — every row prints its own question twice: `titleOf(row)` falls back to the question when a row has no separate title, and `.ready-row-question` prints it again underneath (ReadyQuestionsScreen.jsx:55-59), so all 20 pending candidates read bold sentence, then the same sentence in grey, then "Onay bekliyor" (admin-ready-questions-suggestions-pending-1366.png, -390.png). The screen is the admin's approval queue and it looks like a rendering mistake on every line.
3. **Start board chart card · both widths** — the board card is ~275 px wide at 1366 and ~330 px at 390, and `_CATEGORY_SHARE_PX = 64` (nl2sql/report/chart.py) promises five categories 320 px of label room the card never has, so the five product names print on top of one another as one smear — at desktop, not only on the phone (start-sales-start-sales-cards-1366.png, landing-empty-state-empty-state-1366.png, new-conversation-clean-start-1366.png, start-purchasing-start-purchasing-cards-1366.png, db-dot-user-ok-header-db-green-1366.png). The board is the first screen a user sees and the one place a chart is the whole card; T377's cap fixes the wide answer card but still overshoots this one.
4. **Header · 390** — the database dot arrives with no words: `.db-status .db-label { display: none }` (web/src/styles.css:1082) leaves a bare 10 px ring sitting right next to the model's green dot, so every phone screen reads "○ ● Hazır" — two dots, one label, and the state M25 exists to show (ok / down / no connection / not measured) is unreadable at 390 in every `-390.png`. The ring for "no connection" and the filled dot for "not measured yet" are both grey at that size.
5. **Admin header · 1366** — `.masthead { flex-wrap: wrap }` (styles.css:101) has no wide-screen counterpart, so with seven nav links the user chip and Çıkış break onto a second row of their own and every admin screen carries a two-row masthead (admin-ready-questions-ready-list-1366.png, admin-connections-connections-list-1366.png, users-screen-users-table-1366.png, rules-screen-validation-rules-list-1366.png, ask-golden-answer-chart-answer-with-chart-1366.png). 1366 is a normal laptop, not a phone; the wrap makes the header look unfinished on the screens an admin lives in.

## Craft ideas
6. The board card's refresh is silent while it works — `Yenile` disables and the number changes some time later with no sign the card is doing anything (start-sales-start-sales-cards-1366.png). A short shimmer on the card body while the request is in flight would make the one live control on the board feel live; the 429 note ("28 sn sonra") already proves the card knows it is busy.
7. The clarification card is the best-written screen in the app and looks the least pressable: `.clarification-option` has no CSS rule at all, so the three options are plain buttons with a static "→" parked at the far edge (ask-ambiguous-clarify-then-answer-clarification-card-1366.png, -390.png). A hover/focus lift with the arrow sliding a few px would tell a first-time user that the row, not the arrow, is the thing to hit.

## Checked, not problems
The 401 lines are the pre-login `/api/auth/me` probe, the 409 is `analist2` from the 390 pass, the 429 is the card refresh guard, the mid-page header with the black band is sticky-header stitching, "Satır sayısı N." is the fake narrator and the one-sided "1 satır indirildi" is its token. `landing-empty-state` shows cards because its steps only log in and shoot — nothing clears the board, so the name is the flow's, not the page's. The `en-*` timeouts are `from: M28` flows whose English UI does not exist yet. The clipped nav row is the scrollable `.masthead-nav` mid-scroll and its edge fades are there. The hollow db ring is state `none`, correct for `vitrin_kapali`, which has no stored connection — `db-dot-user-down` never reaches down/red because `admin-connections` times out on the second `#conn-test` (the button stays "Deneniyor…" and disabled), so no connection is ever saved and the ask answers instead of failing fast; that is the flow's order of operations, not the banner's. The doubled red outline on the rules and users error boxes is the deliberate programmatic-focus ring at styles.css:1920. "Kullanıcı adı ya da parola hatalı." is correct Turkish. `conversation-chart-refine` answers every turn with the city-count golden because its questions are not in `datasets/wwi/golden.jsonl`.
